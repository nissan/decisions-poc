# Narrated demo brief

Show engineers a planned task run through a rule baseline and Gemini Decisions with the same eligible lanes. Explain which provider/model/effort tuple gets suggested, how budget and authorization constrain the choice, and when the tool asks for human review. Demonstrate the running CLI and paired-run results, not UI mockups or hand-entered output. If Gemini adds no value, show the observed result and say so.

**Master:** 16:9, 1080p target, 90 seconds maximum, English captions as WebVTT and SRT. Six replaceable scenes in [the manifest](manifest.json), hard cuts, no music or camera required. Keep narration separate. Default to a disclosed, non-cloned synthetic voice rendered locally (Kokoro if already available); authentic narration requires an explicit recording step and a new audio selection. Do not acquire microphone or camera access implicitly.

Use only original planning fixtures, scrubbed terminal captures, and labelled result cards sourced from a recorded run. Show a correct recommendation, a refusal to suggest a lane, and measured results with sample size. Label all downstream costs as forecasts; no agents ran. Use a clean terminal profile and disable capture of home paths, tokens, real quota, account names, private tabs and notifications. Edited playback timing is not a latency measurement. Do not use earlier projects' takes, media, branding or private references.

Capture numbered immutable takes and record source hashes. Resolve only explicit selections in a selected-take manifest; output a new render version for each revision. Keep screen, audio and caption sources separate and local. Before review: full decode, format/duration, speech loudness and sync, caption timing, representative frames, privacy and a claim-to-evidence pass; record the exact render hash. Open that render for the owner's local review before any upload; publication requires separate destination and visibility approval. Nothing has been recorded or approved at kickoff.
